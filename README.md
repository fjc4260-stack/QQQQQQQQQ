# Aparat Chat Logger

این پروژه یک صفحهٔ چت لایو (مثل چت لایو استریم آپارات) را با یک مرورگر مخفی (headless) باز نگه می‌دارد و هر متن جدیدی که روی صفحه ظاهر شود را در MongoDB Atlas ذخیره می‌کند.

## چطور کار می‌کند؟

برنامه صفحه را در پس‌زمینه باز نگه می‌دارد، هر چند ثانیه یک‌بار کل متن صفحه را می‌خواند، خط‌های جدیدی که قبلاً دیده نشده‌اند را پیدا می‌کند و آن‌ها را در دیتابیس ذخیره می‌کند.

**محدودیت مهم:** چون این روش عمومی است (بدون شناخت دقیق ساختار چت)، ممکن است علاوه بر پیام‌های چت، متن‌های دیگر صفحه (مثل تعداد بازدید یا دکمه‌ها) هم ذخیره شوند. اگر بعداً بخواهی فقط پیام‌های خالص چت ذخیره شود، باید ساختار HTML چت را بررسی کنیم و اسکریپت را دقیق‌تر کنیم.

## عیب‌یابی: خطای «Could not find Chrome»

اگه توی لاگ‌های Render این خطا رو دیدی:

```
Error: Could not find Chrome (ver. ...)
```

علتش اینه که Puppeteer به‌طور پیش‌فرض Chrome رو در پوشه خانگی سیستم (`$HOME/.cache`) ذخیره می‌کنه، اما Render این پوشه رو بین مرحلهٔ نصب (Build) و مرحلهٔ اجرا (Start) به‌درستی حفظ نمی‌کنه. برای همین یه فایل `.puppeteerrc.cjs` توی پروژه گذاشته شده که مسیر ذخیره Chrome رو به **داخل خود پوشه پروژه** منتقل می‌کنه (که این پوشه بین Build و Start حفظ می‌شه).

برای رفعش:

1. مطمئن شو فایل `.puppeteerrc.cjs` رو هم توی گیت‌هاب آپلود کردی (کنار `package.json`، نه داخل یه پوشه دیگه).
2. مطمئن شو `package.json` آخرین نسخه رو داری (خط `postinstall` باید این باشه: `npm install puppeteer && npx puppeteer browsers install chrome`).
3. توی تنظیمات Render، **Build Command** رو بذار: `npm install`
4. حتماً از منوی **Manual Deploy → Clear build cache & deploy** استفاده کن، نه دیپلوی معمولی — چون کش بیلد قبلی بدون این تنظیم ذخیره شده.
5. توی لاگ‌های مرحله Build دنبال خطی بگرد که دانلود Chrome رو نشون بده.

اگه بازم همون خطا اومد، احتمالاً فایل `.puppeteerrc.cjs` درست آپلود نشده — اسمش باید دقیقاً با نقطهٔ اول (`.puppeteerrc.cjs`) باشه، نه بدون نقطه.

## مرحله ۰ (اختیاری، توصیه‌شده): تست اولیه بدون MongoDB

قبل از این‌که وقت بذاری برای ساخت حساب MongoDB Atlas، می‌تونی اول با یه نسخه آزمایشی مطمئن بشی که اصلاً صفحه چت روی Render باز می‌شه یا نه. فایل `index.test.js` دقیقاً برای همینه — هیچ نیازی به MongoDB نداره و فقط پیام‌ها رو به‌جای ذخیره در دیتابیس، توی لاگ‌های Render نشون می‌ده.

برای استفاده از این حالت:

1. توی تنظیمات Render، فیلد **Start Command** رو به‌جای `npm start`، بذار: `npm run start:test`
2. فقط همین یکی متغیر محیطی رو تنظیم کن: `CHAT_URL` = `https://www.aparat.com/alirezask1547/live/chat` (نیازی به `MONGO_URI` نیست)
3. بعد از دیپلوی، توی بخش **Logs** باید ببینی که می‌گه "صفحه با موفقیت باز شد" و بعدش خط‌های متنی که از چت خونده می‌شه.
4. همچنین اگه آدرس Render‌ت رو باز کنی (مثلاً `https://your-app-name.onrender.com`)، یه صفحه JSON می‌بینی که ۲۰ خط آخری که دیده شده رو نشون می‌ده.

وقتی مطمئن شدی این نسخه درست کار می‌کنه، برو سراغ ساخت حساب MongoDB Atlas (مرحله ۱ زیر)، و بعد **Start Command** رو دوباره برگردون به `npm start` و متغیر `MONGO_URI` رو هم اضافه کن.

## مرحله ۱: ساخت دیتابیس در MongoDB Atlas

1. وارد [mongodb.com/atlas](https://www.mongodb.com/atlas) شو و یک حساب رایگان بساز.
2. یک Cluster رایگان (Free Tier / M0) بساز.
3. در بخش **Database Access** یک کاربر با نام کاربری و رمز عبور بساز.
4. در بخش **Network Access** روی Add IP Address بزن و گزینه `Allow Access from Anywhere` (یعنی `0.0.0.0/0`) را انتخاب کن (چون Render از IP ثابت استفاده نمی‌کند).
5. روی دکمه **Connect** کلاستر بزن، گزینه **Drivers** را انتخاب کن و رشتهٔ اتصال (Connection String) را کپی کن. شبیه این است:
   ```
   mongodb+srv://username:password@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

## مرحله ۲: بالا بردن پروژه روی گیت‌هاب

Render برای دیپلوی نیاز دارد پروژه در یک ریپازیتوری گیت (مثلاً GitHub) باشد. اگر با گیت‌هاب آشنا نیستی:

1. یک ریپازیتوری جدید در [github.com](https://github.com) بساز.
2. تمام فایل‌های این پوشه (`package.json`, `index.js`, `.env.example`, `README.md`) را در آن آپلود کن (از دکمه "Add file" → "Upload files" در گیت‌هاب استفاده کن).
3. **فایل `.env` واقعی را هرگز آپلود نکن** — رمزهای عبور در آن است. فقط `.env.example` باید در گیت‌هاب باشد.

## مرحله ۳: دیپلوی روی Render (به‌عنوان Web Service رایگان)

توجه: در Render، **Background Worker پلن رایگان ندارد** (حداقل هزینه‌اش ۷ دلار در ماه است). به همین دلیل این پروژه را به‌صورت **Web Service** دیپلوی می‌کنیم که پلن رایگان دارد؛ فقط یک سرور HTTP کوچک هم داخل کد اضافه شده که صرفاً یک صفحه وضعیت ساده نشان می‌دهد (نیازی نیست کاری با آن بکنی، فقط باعث می‌شود Render این سرویس را قبول کند).

1. وارد [render.com](https://render.com) شو و حساب بساز (می‌توانی با گیت‌هاب وارد شوی).
2. روی **New +** بزن و **Web Service** را انتخاب کن.
3. ریپازیتوری گیت‌هابت را انتخاب کن.
4. تنظیمات زیر را وارد کن:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
5. در بخش **Environment Variables** این مقادیر را اضافه کن:
   - `MONGO_URI` = رشتهٔ اتصالی که از Atlas گرفتی
   - `CHAT_URL` = `https://www.aparat.com/alirezask1547/live/chat`
   - `DB_NAME` = `aparat_chat`
   - `COLLECTION_NAME` = `messages`
   - `POLL_INTERVAL_MS` = `3000`
6. پلن **Free** را انتخاب کن. **نکته مهم:** حافظه (RAM) پلن رایگان کم است و ممکن است اجرای مرورگر Chrome با کرش مواجه شود. اگر مدام کرش دیدی، تنها راه‌حل ارتقا به پلن Starter (پولی) است.
7. روی **Create Web Service** بزن.
8. بعد از دیپلوی، Render یک آدرس به شکل `https://your-app-name.onrender.com` بهت می‌دهد. این را یادداشت کن، چون در مرحله بعد لازمش داری.

## مرحله ۴: جلوگیری از خواب رفتن سرویس (cron-job.org)

سرویس‌های رایگان Render اگر ۱۵ دقیقه هیچ درخواست HTTP دریافت نکنند، «می‌خوابند» و برنامه پیام‌خوانی هم متوقف می‌شود. برای جلوگیری از این:

1. وارد [cron-job.org](https://cron-job.org) شو و یک حساب رایگان بساز.
2. روی **Create cronjob** بزن.
3. در قسمت **URL**، همان آدرس Render‌ت را وارد کن (مثلاً `https://your-app-name.onrender.com`).
4. بازهٔ زمانی (**Schedule**) را روی هر **۱۰ دقیقه یک‌بار** تنظیم کن.
5. ذخیره کن.

از این به بعد، cron-job.org هر ۱۰ دقیقه یک‌بار به آدرس سرویست سر می‌زند و اجازه نمی‌دهد Render آن را بخواباند.

## مرحله ۵: بررسی اینکه کار می‌کند

در بخش **Logs** همان صفحه در Render، باید خط‌هایی شبیه این ببینی:

```
[mongo] با موفقیت به MongoDB Atlas متصل شد.
[page] صفحه با موفقیت باز شد.
[main] پایش پیام‌ها آغاز شد...
[save] <متن پیام>
```

اگر پیام خطایی دیدی که مربوط به کمبود حافظه یا کرش مرورگر بود (چیزی شبیه `Target closed` یا `Protocol error`)، یعنی باید پلن Render را ارتقا بدهی.

همچنین اگر آدرس Render‌ت را مستقیم در مرورگر باز کنی (مثلاً `https://your-app-name.onrender.com`)، یک صفحهٔ JSON ساده می‌بینی که وضعیت لحظه‌ای برنامه (وصل بودن به Mongo، باز بودن صفحه، تعداد پیام‌های ذخیره‌شده) را نشان می‌دهد.

## دیدن پیام‌های ذخیره‌شده

می‌توانی از طریق پنل **MongoDB Atlas → Browse Collections** مستقیم پیام‌ها را ببینی، یا بعداً از من بخواهی یک صفحهٔ ساده برای نمایش آن‌ها بسازم.
